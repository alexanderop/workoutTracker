### Fix 1: benchmarkHelpers.ts import error (2026-01-18)
**Tests fixed:** 5 test suites (benchmark-execution, benchmark-management, benchmark-results, benchmark-ui, benchmark-ux-simplification)

**Issue:** `benchmarkHelpers.ts` imported `userEvent` directly from `vitest/browser`:
```ts
import { userEvent } from 'vitest/browser'
```
This import fails in Happy-DOM mode because `vitest/browser` can only be imported in Browser Mode.

**Fix:** Changed to use the project's abstraction layer which auto-detects the environment:
```ts
import { page, userEvent } from '../../helpers/locator'
```

**Verification:** All benchmark test suites now load correctly in both Happy-DOM and browser mode.

### Fix 2: exercise-store-partial-update.spec.ts isBrowserMode detection (2026-01-18)
**Test fixed:** `preserves image when updating only name` in `exercise-store-partial-update.spec.ts`

**Issue:** The test used a flawed browser detection approach that checked `navigator.userAgent`:
```ts
const isBrowserMode =
  globalThis.window !== undefined &&
  !globalThis.navigator.userAgent.includes('jsdom') &&
  !globalThis.navigator.userAgent.includes('Happy DOM')
```
This detection was not working correctly, causing the Blob-related test to run in Happy-DOM mode instead of being skipped (fake-indexeddb doesn't properly handle Blob objects).

**Fix:** Changed to use the standard project pattern that checks for `__vitest_browser__`:
```ts
const isBrowserMode =
  globalThis.window !== undefined && '__vitest_browser__' in globalThis
```

**Verification:**
- Happy-DOM: Test properly skipped (5 tests | 1 skipped), other 4 tests pass
- Browser mode: All 5 tests pass (Blob test runs correctly)

### Fix 3: add-block-dialog-viewport.spec.ts browser-only APIs (2026-01-18)
**Tests fixed:** 2 tests in `add-block-dialog-viewport.spec.ts`

**Issue:** The test file used browser-only APIs that don't exist in Happy-DOM:
- `page.viewport()` for setting viewport size
- `expect.element()` for visibility assertions

These APIs are only available in Vitest browser mode, causing the tests to fail with:
```
TypeError: __vite_ssr_import_0__.page.viewport is not a function
```

**Fix:** Added browser mode detection and skip the entire test suite in Happy-DOM mode:
```ts
const isBrowserMode =
  globalThis.window !== undefined && '__vitest_browser__' in globalThis

describe.skipIf(!isBrowserMode)('AddBlockDialog - Desktop Viewport Clipping', () => {
```

Also removed unused import `expectElement, expectPoll` from assertions.

**Verification:**
- Happy-DOM: 2 tests skipped (browser-only test suite correctly skipped)
- Browser mode: 2 tests pass

### Fix 5: benchmarkHelpers.ts expect.element() browser-only API (2026-01-18)
**Tests fixed:** Multiple benchmark test suites using `startBenchmarkWorkout` and `waitForCompletionScreen`

**Issue:** `benchmarkHelpers.ts` used `expect.element()` directly instead of the project's `expectElement` abstraction:
```ts
await expect.element(page.getByRole('button', { name: /tap to advance/i })).toBeVisible()
await expect.element(page.getByText(/workout complete/i)).toBeVisible()
```
`expect.element()` is a browser-only API (Vitest browser mode), causing tests to fail in Happy-DOM with:
```
TypeError: __vite_ssr_import_1__.expect.element is not a function
```

**Fix:** Changed to use the `expectElement` function from the assertions abstraction layer:
```ts
await expectElement(page.getByRole('button', { name: /tap to advance/i })).toBeVisible()
await expectElement(page.getByText(/workout complete/i)).toBeVisible()
```
Also removed unused `expectPoll` import.

**Verification:**
- Happy-DOM: Tests now pass/skip correctly
- Browser mode: `displays completion screen with final time` test passes
