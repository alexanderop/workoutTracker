🛡️ ESLint Enforcement

ESLint rules prevent hardcoded route strings at build time (eslint.config.ts lines 156-166):

// ❌ FORBIDDEN - ESLint will block these:
router.push('/workouts')
router.push(`/workouts/${id}`)

// ✅ REQUIRED - Type-safe named routes:
router.push({ name: RouteNames.Workouts })
router.push({ name: RouteNames.WorkoutDetail, params: { id } })

✅ Always use RouteNames enum for navigation. ESLint will catch hardcoded strings and prevent builds.

📊 Route Structure & Flows

Flat hierarchy with 13 top-level routes. No nested routes. Dynamic segments passed as props via props: true.

Pattern 1: Workout Execution Flow

Flow: Home → ActiveWorkout → WorkoutSummary → Home

  workout.value.name = name
  await saveNow()

      name: RouteNames.WorkoutSummary,

Flow: WorkoutDetail → ActiveWorkout

  isRedoing.value = true

    getWorkoutsRepository().startFromCompleted(id)
  )

Pattern: Copy completed workout to active workout, then resume (which navigates).

🛡️ Route Guards & Initialization

No traditional route guards (beforeEach, beforeEnter, afterEach) are used.

Instead, app-level initialization handles edge cases like resuming workouts.

App Initialization Pattern

Resume workout prompt (src/features/workout/composables/useAppInitialization.ts):

export function useAppInitialization() {
  async function initialize(): Promise<void> {
    // Load settings and exercises
    await Promise.all([
      settingsStore.loadFromDb(),
      exercisesStore.loadFromDb()
    ])

    // Check for active workout
    const activeWorkout = await getActiveWorkoutRepository().get()

    if (activeWorkout && activeWorkout.blocks.length > 0) {
      // Prompt user to resume
      initState.value = {
        status: 'prompt-resume',
        workoutName: activeWorkout.name,
        blockCount: activeWorkout.blocks.length,
      }
      return
    }

    initState.value = { status: 'ready' }
  }

  async function resumeWorkout(): Promise<void> {
    const savedWorkout = await persistence.loadActiveWorkout()

    if (savedWorkout) {
      restoreWorkout(savedWorkout)
      persistence.markInitialized()
    }

    initState.value = { status: 'ready' }

    // Navigate to active workout
    await tryCatch(
      router.push({ name: RouteNames.ActiveWorkout })
    )
  }
}

Called in App.vue (onMounted):

onMounted(() => {
  initialize()
})

// Shows dialog if workout exists
<ResumeWorkoutDialog
  :open="showResumeDialog"
  @resume="resumeWorkout"
  @discard="discardWorkout"
/>

Pattern: App-level initialization prompts user before auto-navigation, rather than using route guards.

💡 Architectural Insights

Key characteristics of the routing architecture:

  • Simple & Flat - 13 top-level routes, no nested routes, easy to understand
  • Type-Safe - RouteNames enum prevents typos, ESLint enforces usage at build time
  • View-Driven - Navigation logic lives in views, not features (architectural boundary)
  • Props Mode - Dynamic route params passed as props via props: true config
  • No Custom Utilities - Uses native Vue Router APIs directly (useRouter, useRoute)
  • No Route Guards - App-level initialization handles edge cases like resume flows
  • Clean Separation - Features focus on business logic, views handle routing concerns

⚡ Why this works: Simple patterns scale better than complex abstractions. Type safety prevents bugs. Clear boundaries enable team collaboration.
