Migrating to localStorage

Step-by-step guide to switch from IndexedDB to localStorage using the Repository Pattern.

🎯 Repository Pattern Benefits

The Repository Pattern abstracts data storage. This means you can swap IndexedDB for localStorage without changing your app code!

💡 Key insight: Your components only know about repository interfaces, not implementations.

📋 Migration Process

Here's the complete migration flow:

🤔 Why Switch to localStorage?

Pros:

  • ✅ Simpler - No Dexie dependency, just native browser APIs
  • ✅ Synchronous - No async/await needed (easier debugging)
  • ✅ Smaller bundle - Remove Dexie from dependencies
  • ✅ Easier to inspect - View data directly in DevTools

Cons:

  • ❌ Size limit - ~5-10MB max (IndexedDB handles GBs)
  • ❌ No indexing - Slower queries on large datasets
  • ❌ No transactions - Less robust data integrity
  • ❌ Blocking - Large reads/writes freeze UI

⚠️ Recommendation: Use localStorage only if your data stays small (<1MB).

🛠️ Implementation Steps

Step 1: Create localStorage Implementation Folder

src/db/implementations/
├── dexie/           # Current implementation
└── localstorage/    # New implementation (create this)
    ├── customExercises.ts
    ├── workouts.ts
    ├── settings.ts
    └── ...

Step 2: Implement One Repository

Example: src/db/implementations/localstorage/customExercises.ts

import type { CustomExercisesRepository } from '@/db/interfaces'
import type { DbCustomExercise } from '@/db/schema'

const STORAGE_KEY = 'customExercises'

function getExercises(): Array<DbCustomExercise> {
  const raw = localStorage.getItem(STORAGE_KEY)
  return raw ? JSON.parse(raw) : []
}

function saveExercises(exercises: Array<DbCustomExercise>): void {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(exercises))
}

export function createLocalStorageCustomExercisesRepository(): CustomExercisesRepository {
  return {
    async getAll(): Promise<ReadonlyArray<DbCustomExercise>> {
      return getExercises()
    },

    async getById(id: string): Promise<DbCustomExercise | undefined> {
      const exercises = getExercises()
      return exercises.find(ex => ex.id === id)
    },

    async add(exercise: Readonly<DbCustomExercise>): Promise<void> {
      const exercises = getExercises()
      exercises.push(exercise as DbCustomExercise)
      saveExercises(exercises)
    },

    async update(
      id: string,
      updates: Partial<Omit<DbCustomExercise, 'id' | 'createdAt'>>
    ): Promise<void> {
      const exercises = getExercises()
      const index = exercises.findIndex(ex => ex.id === id)

      if (index === -1) {
        throw new Error('Exercise not found')
      }

      exercises[index] = {
        ...exercises[index],
        ...updates,
        updatedAt: Date.now(),
      }

      saveExercises(exercises)
    },

    async delete(id: string): Promise<void> {
      const exercises = getExercises()
      const filtered = exercises.filter(ex => ex.id !== id)
      saveExercises(filtered)
    },

    async existsByName(name: string): Promise<boolean> {
      const exercises = getExercises()
      return exercises.some(
        ex => ex.name.toLowerCase() === name.toLowerCase()
      )
    },

    async searchByName(query: string): Promise<ReadonlyArray<DbCustomExercise>> {
      const exercises = getExercises()
      const lowerQuery = query.toLowerCase()
      return exercises.filter(
        ex => ex.name.toLowerCase().includes(lowerQuery)
      )
    },
  }
}

Step 3: Update Provider

Modify src/db/provider.ts to use your new localStorage implementation:

// Change from:
import { createDexieCustomExercisesRepository } from './implementations/dexie/customExercises'

// To:
import { createLocalStorageCustomExercisesRepository } from './implementations/localstorage/customExercises'

// Then update the provider:
function createRepositoryProvider(): RepositoryProvider {
  return {
    customExercises: createLocalStorageCustomExercisesRepository(),
    // ... other repositories
  }
}

Step 4: Implement Remaining Repositories

Follow the same pattern for:

  • workouts.ts - Use key workouts
  • settings.ts - Use key settings
  • activeWorkout.ts - Use key activeWorkout
  • templates.ts - Use key templates
  • benchmarks.ts - Use key benchmarks

💡 Tip: Migrate one repository at a time and test before moving to the next!

Step 5: Remove Dexie Dependency

Once all repositories are migrated:

# Remove Dexie from package.json
pnpm remove dexie

# Delete old implementation
rm -rf src/db/implementations/dexie

🧪 Testing Considerations

Mock localStorage in tests:

// In your test setup
global.localStorage = {
  getItem: vi.fn(),
  setItem: vi.fn(),
  removeItem: vi.fn(),
  clear: vi.fn(),
}

// Reset before each test
beforeEach(() => {
  vi.clearAllMocks()
  localStorage.clear()
})

⚡ Performance Optimization

For larger datasets, consider:

  • Debouncing writes - Don't save on every update
  • Lazy loading - Parse JSON only when needed
  • Separate keys - Don't store everything in one massive object
  • Compression - Use LZ-string library for large data
// Example: Debounced save
import { debounce } from 'lodash-es'

const debouncedSave = debounce((data) => {
  localStorage.setItem(KEY, JSON.stringify(data))
}, 300)

🔄 Data Migration

Moving existing IndexedDB data to localStorage:

// 1. Export data from IndexedDB
import { getDataManagementRepository } from '@/db'
const data = await getDataManagementRepository().exportAllData()

// 2. Save to localStorage
localStorage.setItem('workouts', JSON.stringify(data.workouts))
localStorage.setItem('customExercises', JSON.stringify(data.customExercises))
// ... etc

// 3. Switch implementation in provider.ts

// 4. Reload app - data is now in localStorage!

⚠️ Important: Always backup data before migrating!
