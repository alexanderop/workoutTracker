Database Layer

Repository Pattern with Dexie.js for offline-first IndexedDB persistence.

🗄️ Architecture Overview

The database layer uses the Repository Pattern to abstract IndexedDB operations:

📁 File Structure

🎯 Key Concepts

1️⃣ Repository Interfaces

Define contracts for data access - implementations can be swapped:

// src/db/interfaces.ts
export type WorkoutsRepository = {
  getAll(): Promise<Array<DbCompletedWorkout>>
  getById(id: string): Promise<DbCompletedWorkout | undefined>
  create(workout: DbCompletedWorkout): Promise<DbCompletedWorkout>
  delete(id: string): Promise<void>
}

2️⃣ Db* Types vs Domain Types

  • Database types (Db* prefix): Use null for "no value" (IndexedDB requirement)
  • Domain types (no prefix): Use undefined for optional values
// Database type
type DbCustomExercise = {
  equipment: Equipment | null  // IndexedDB-compatible
}

// Domain type
type Exercise = {
  equipment?: Equipment  // App logic uses undefined
}

3️⃣ Type Converters

Transform between database and domain types:

import { convertWorkoutToDb, convertDbToWorkout } from '@/db/converters'

// Domain → Database
const dbWorkout = convertWorkoutToDb(workout)
await getWorkoutsRepository().create(dbWorkout)

// Database → Domain
const workout = convertDbToWorkout(dbWorkout)

✅ Usage Pattern

Always use repository getters from @/db/index.ts:

import { getWorkoutsRepository, generateId } from '@/db'

const repo = getWorkoutsRepository()

// Create
const workout = { id: generateId(), /* ... */ }
await repo.create(workout)

// Read
const allWorkouts = await repo.getAll()
const oneWorkout = await repo.getById(id)

// Delete
await repo.delete(id)

❌ Never import Dexie directly (except in tests). Always use repository getters.

💡 Benefits

  • Abstraction - Easy to swap implementations (e.g., move to SQL later)
  • Testing - Mock repositories in tests without touching real database
  • Type Safety - TypeScript ensures correct usage
  • Offline First - IndexedDB works without network
  • Consistency - Single source of truth for data operations
