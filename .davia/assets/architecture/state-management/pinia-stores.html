Pinia Stores

Domain-level state cache for frequently-accessed data. Stores act as a synchronization layer between the database and components.

💾 What Stores Manage

Stores are for persistent, frequently-accessed domain data:

  • 📚 Exercise library - Custom exercises (loaded once, accessed everywhere)
  • ⚙️ User settings - Preferences, units, theme (loaded once, rarely changes)
  • 🎯 Hot data - Data that needs to be instantly available across many components

⚡ Key Benefit: After initial load, all store access is synchronous (no awaits!)

🔄 Store Patterns

1. Load-Once Pattern

Stores load data once at app initialization, then all access is synchronous.

// src/composables/useAppInitialization.ts:35-77
async function initialize() {
  // Load stores in parallel
  await Promise.all([
    settingsStore.loadFromDb(),
    exercisesStore.loadFromDb()
  ])

  // After this, all access is synchronous!
  const exercises = exercisesStore.getAllExercises() // No await!
}

2. DB-First Update Pattern

Always save to database first, then update the store cache.

// src/stores/exercises.ts:33-45
async function addExercise(exercise: Omit<CustomExercise, 'id'>) {
  const dbExercise = createDbCustomExercise(exercise)

  // 1. Save to DB first (persistent)
  await getCustomExercisesRepository().add(dbExercise)

  // 2. Convert to domain type
  const newExercise = dbToCustomExercise(dbExercise)

  // 3. Update cache
  customExercises.value = [...customExercises.value, newExercise]

  return newExercise
}

3. Validation Pattern

Validate and clamp values before saving.

// src/stores/settings.ts:64-70
async function setTimerSoundVolume(volume: number): Promise<void> {
  // Clamp to valid range
  const clampedVolume = Math.max(0.5, Math.min(1.0, volume))

  await getSettingsRepository().set({
    key: 'timerSoundVolume',
    value: clampedVolume
  })
  timerSoundVolume.value = clampedVolume
}

✅ Use Stores When...

  • ✅ Data is accessed frequently across many components
  • ✅ Data is loaded once and rarely changes
  • ✅ You need synchronous access (no awaits in components)
  • ✅ Data represents domain-level state (exercises, settings)

❌ Don't Use Stores When...

  • ❌ Data is temporary or component-specific (use composables)
  • ❌ Data changes frequently (use reactive refs in composables)
  • ❌ Data is only used in one place (use local component state)
  • ❌ You need complex business logic (use composables)

🔗 Integration with Other Layers

Stores → Repositories:

  • Stores call repositories for DB operations
  • Example: getCustomExercisesRepository().add()

Composables → Stores:

  • Composables read from stores for cached data
  • Example: useExerciseSearch uses exercisesStore.customExercises

Components → Stores:

  • Components can directly access store data (synchronous)
  • Example: const store = useExercisesStore(); const exercises = store.getAllExercises()
