Composables

Business logic + temporary state. Composables encapsulate reusable logic and bridge between stores, repositories, and components.

🧩 What Composables Manage

Composables handle temporary, derived, or behavioral state:

  • 🔄 Data fetching - Load from repositories, cache temporarily
  • 🎛️ Filtering/search - Derive state from stores or props
  • 🤝 Coordination - Bridge between layers (DB ↔ memory)
  • ⏱️ State machines - Timers, workflows with enforced transitions

💡 Key Benefit: Composables are reusable and testable - extract once, use everywhere.

📊 Composable Patterns

1. Fetch + Cache Pattern

Load data from repositories, cache in refs for component use.

Example: useWorkoutsList.ts (lines 1-54)

export function useWorkoutsList() {
  const workouts = ref<Array<CompletedWorkout>>([])
  const templates = ref<Array<Template>>([])
  const isLoading = ref(true)

  async function loadAll() {
    const [workoutList, templateList] = await Promise.all([
      getWorkoutsRepository().getHistory(),
      getTemplatesRepository().getAll()
    ])
    workouts.value = workoutList
    templates.value = templateList
    isLoading.value = false
  }

  onMounted(() => loadAll())

  return { workouts, templates, isLoading, loadAll }
}

Use when:

  • ✅ Data is loaded per-component (not globally cached)
  • ✅ You need loading states for the UI
  • ✅ Data comes from multiple repositories in parallel

2. Filter + Derive Pattern

Read from stores, compute filtered/derived results reactively.

Example: useExerciseSearch.ts (lines 73-100)

export function useExerciseSearch(options?: UseExerciseSearchOptions) {
  const exercisesStore = useExercisesStore()
  const searchQuery = ref('')

  const allExercises = computed(() => {
    return [...exercisesStore.customExercises].toSorted(...)
  })

  const filteredExercises = computed(() => {
    let result = allExercises.value
    result = filterByMuscle(result, options?.muscleFilter.value)
    result = filterBySearchQuery(result, searchQuery.value, ['name'])
    return result
  })

  return { searchQuery, filteredExercises, allExercises }
}

Use when:

  • ✅ Deriving state from store data
  • ✅ Reactive filtering or transformations
  • ✅ Multiple computed dependencies

3. Coordinate Pattern

Bridge between layers - watch changes, convert types, save to DB.

Example: useWorkoutPersistence.ts (lines 50-81)

export function useWorkoutPersistence() {
  const workout = getWorkoutRef() // Singleton state
  const persistenceState = ref<PersistenceState>({ status: 'idle' })

  // Auto-save: watch changes, debounce, convert, save
  watchDebounced(
    workout,
    async (newWorkout) => {
      if (newWorkout.blocks.length === 0) {
        await getActiveWorkoutRepository().clear()
        return
      }

      persistenceState.value = { status: 'saving' }

      // Convert domain type → DB type
      const dbWorkout = workoutToDb(newWorkout, currentWorkoutStartedAt)

      // Save to repository
      await getActiveWorkoutRepository().save(dbWorkout)

      persistenceState.value = { status: 'idle' }
    },
    { debounce: 1000, deep: true }
  )

  return { persistenceState, loadActiveWorkout, completeWorkout, discardWorkout }
}

Use when:

  • ✅ Coordinating between in-memory state and database
  • ✅ Auto-saving with debounce
  • ✅ Type conversions (domain ↔ DB)

4. State Machine Pattern

Enforce state transitions with clear status tracking.

Example: useBaseTimer.ts (lines 1-150)

export function useBaseTimer() {
  const status = ref<TimerStatus>('idle')
  const elapsedMs = ref(0)
  const startedAt = ref<number | undefined>()

  function start() {
    if (status.value === 'running') return
    status.value = 'running'
    startedAt.value = Date.now()
  }

  function pause() {
    if (status.value !== 'running') return
    status.value = 'paused'
  }

  function complete() {
    if (status.value === 'idle') return
    status.value = 'completed'
  }

  // Readonly outputs to prevent mutations
  return {
    status: readonly(status),
    elapsedMs: readonly(elapsedMs),
    start,
    pause,
    complete
  }
}

Use when:

  • ✅ Enforcing state transitions (idle → running → paused → completed)
  • ✅ Preventing invalid operations
  • ✅ Readonly outputs to avoid accidental mutations

✅ Use Composables When...

  • ✅ Logic is reusable across components
  • ✅ State is temporary or component-specific
  • ✅ You need business logic (validation, formatting, coordination)
  • ✅ Bridging between stores and repositories
  • ✅ Managing derived/computed state

❌ Don't Use Composables When...

  • ❌ Data is globally cached (use stores instead)
  • ❌ State is trivial and only used once (use local component state)
  • ❌ You just need database access (call repositories directly from composables)

🔗 Integration with Other Layers

Composables → Stores:

  • Read cached data from stores
  • Example: useExerciseSearch reads from exercisesStore (line 74)

Composables → Repositories:

  • Call repositories directly for DB operations
  • Example: useWorkoutsList calls getWorkoutsRepository() (line 34)

Components → Composables:

  • Components call composables for logic + state
  • Example: const { workouts, isLoading } = useWorkoutsList()
