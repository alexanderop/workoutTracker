Composable Testing

⚙️ Unit testing Vue 3 composables with and without lifecycle hooks

🎯 What Are Composable Tests?

Composable tests verify the behavior of Vue Composition API functions in isolation.

They test:

  • ✅ Reactive state management
  • ✅ Computed properties
  • ✅ Methods and side effects
  • ✅ Lifecycle hook integration
  • ✅ Dependency injection (provide/inject)

📍 Location

src/__tests__/composables/

Example files:

  • timers/useBaseTimer.spec.ts - Direct composable test
  • useDialogState.spec.ts - Lifecycle-dependent composable

🔀 Decision Tree: Which Testing Approach?

✅ Direct Testing (No Lifecycle Hooks)

Use when: Composable doesn't use onMounted, onUnmounted, inject, provide, or other lifecycle hooks

Example: Simple Timer Composable

import { useRestTimer } from '@/composables/timers/useRestTimer'

describe('useRestTimer', () => {
  it('starts a timer with given duration', () => {
    const { start, isRunning, timeRemaining } = useRestTimer()

    start(60)

    expect(isRunning.value).toBe(true)
    expect(timeRemaining.value).toBe(60)
  })

  it('stops a running timer', () => {
    const { start, stop, isRunning } = useRestTimer()

    start(60)
    stop()

    expect(isRunning.value).toBe(false)
  })
})

No cleanup required - composable is called directly

🔄 withSetup Testing (Lifecycle Hooks)

Use when: Composable uses Vue lifecycle hooks or dependency injection

File: src/__tests__/helpers/withSetup.ts

What withSetup Provides

  • 🔄 Component lifecycle (onMounted, onUnmounted)
  • 📦 Dependency injection (provide/inject)
  • 🎯 Full Vue component context

Example: Dialog State Composable

import { withSetup } from '@/__tests__/helpers/withSetup'
import { useDialogState } from '@/composables/useDialogState'

describe('useDialogState', () => {
  it('initializes with closed state', () => {
    const [result, app] = withSetup(() => useDialogState())

    expect(result.isOpen.value).toBe(false)

    app.unmount() // ✅ Required cleanup
  })

  it('opens and closes dialog', () => {
    const [result, app] = withSetup(() => useDialogState())

    result.open()
    expect(result.isOpen.value).toBe(true)

    result.close()
    expect(result.isOpen.value).toBe(false)

    app.unmount()
  })
})

Cleanup required - must call app.unmount()

🛠️ withSetup API

Signature

function withSetup<T>(composable: () => T): [T, App]

Returns

  • [0] - Result from the composable
  • [1] - Vue App instance (for cleanup)

Usage with Plugins

import { withSetup } from '@/__tests__/helpers/withSetup'
import { createPinia } from 'pinia'

it('uses Pinia store', () => {
  const pinia = createPinia()
  const [result, app] = withSetup(() => useMyComposable(), {
    plugins: [pinia]
  })

  // ... assertions ...

  app.unmount()
})

🎓 Real Examples

Example 1: Direct Test (No Lifecycle)

File: src/__tests__/composables/timers/useBaseTimer.spec.ts

import { useBaseTimer } from '@/composables/timers/useBaseTimer'

describe('useBaseTimer', () => {
  it('increments time every second', async () => {
    vi.useFakeTimers()

    const { start, elapsedSeconds } = useBaseTimer()

    start()

    vi.advanceTimersByTime(3000) // 3 seconds
    expect(elapsedSeconds.value).toBe(3)

    vi.useRealTimers()
  })
})

Example 2: withSetup Test (Lifecycle Hooks)

File: src/__tests__/composables/useDialogState.spec.ts

import { withSetup } from '@/__tests__/helpers/withSetup'
import { useDialogState } from '@/composables/useDialogState'

describe('useDialogState', () => {
  it('triggers onMounted callback', () => {
    const mountedSpy = vi.fn()

    const [result, app] = withSetup(() => {
      const state = useDialogState()
      onMounted(mountedSpy)
      return state
    })

    expect(mountedSpy).toHaveBeenCalled()

    app.unmount()
  })
})

⚠️ Common Pitfalls

❌ Forgetting to Unmount

// ❌ BAD - memory leak
it('my test', () => {
  const [result, app] = withSetup(() => useMyComposable())
  expect(result.value).toBe(true)
  // No unmount!
})

// ✅ GOOD - properly cleaned up
it('my test', () => {
  const [result, app] = withSetup(() => useMyComposable())
  expect(result.value).toBe(true)
  app.unmount()
})

❌ Using withSetup When Not Needed

// ❌ BAD - unnecessary overhead
it('simple composable', () => {
  const [result, app] = withSetup(() => useSimpleCounter())
  expect(result.count.value).toBe(0)
  app.unmount()
})

// ✅ GOOD - call directly
it('simple composable', () => {
  const { count } = useSimpleCounter()
  expect(count.value).toBe(0)
})

💡 Tips & Best Practices

  • ✅ Direct test when possible (simpler, faster)
  • ✅ Use withSetup only for lifecycle-dependent composables
  • ✅ Always unmount when using withSetup
  • ✅ Use vi.useFakeTimers for timer-based composables
  • ❌ Don't over-test implementation details (test behavior, not internals)
