Test Utilities

🛠️ Reusable helpers, page objects, and test data builders

🎯 What Are Test Utilities?

Test utilities are reusable tools that simplify writing tests.

They include:

  • 🔧 Test Helpers - App rendering, setup/teardown, database reset
  • 📄 Page Objects - Encapsulated UI interactions
  • 🏭 Test Factories - Builders for test data

📍 Location

src/__tests__/
├── helpers/           # Test helpers and page objects
│   ├── pages/        # Page Object implementations
│   ├── createTestApp.ts
│   ├── withSetup.ts
│   ├── integrationSetup.ts
│   └── resetDatabase.ts
└── factories/         # Test data builders

🗺️ Test Utilities Structure

🔧 Test Helpers

createTestApp()

Purpose: Render full application with router, Pinia, and i18n

File: src/__tests__/helpers/createTestApp.ts

Usage:

const app = await createTestApp({ initialRoute: '/' })
// ... interact with app ...
app.cleanup()

withSetup()

Purpose: Test composables with lifecycle hooks

File: src/__tests__/helpers/withSetup.ts

Usage:

const [result, app] = withSetup(() => useMyComposable())
// ... test result ...
app.unmount()

resetDatabase()

Purpose: Reset IndexedDB between tests for isolation

File: src/__tests__/setup.ts

Usage:

beforeEach(async () => {
  await resetDatabase()
})

integrationSetup()

Purpose: Setup and teardown for integration tests

File: src/__tests__/helpers/integrationSetup.ts

Usage:

import { setupIntegrationTest, cleanupIntegrationTest } from '../helpers/integrationSetup'

beforeEach(setupIntegrationTest)
afterEach(cleanupIntegrationTest)

Location: src/__tests__/helpers/pages/

🏭 Test Factories

Purpose: Build test data with fluent API

Location: src/__tests__/factories/

workoutBuilder

File: workout.builder.ts

Purpose: Build in-memory workouts for useWorkout() tests

Usage:

import { workoutBuilder } from '@/__tests__/factories/workout.builder'

const workout = workoutBuilder()
  .withName('Leg Day')
  .withStrengthBlock({ exerciseName: 'Squat' })
  .withExerciseAndSets([
    { kg: 100, reps: 5, rir: 2, completed: true },
    { kg: 100, reps: 5, rir: 2, completed: false },
  ])
  .selectBlock(0)
  .build()

dbWorkoutBuilder

File: dbWorkout.factory.ts

Purpose: Create database workouts for integration tests

Usage:

import { dbWorkoutBuilder } from '@/__tests__/factories/dbWorkout.factory'

const workout = await dbWorkoutBuilder()
  .withExercise('Deadlift', 3)
  .completed()
  .build()

blockFactory

File: block.factory.ts

Purpose: Create workout blocks

Usage:

import { strengthBlock, amrapBlock } from '@/__tests__/factories/block.factory'

const block = strengthBlock({ exerciseName: 'Bench Press' })

setFactory

File: set.factory.ts

Purpose: Create exercise sets

Usage:

exerciseFactory

File: exercise.factory.ts

🎓 Example: Using Everything Together

import { createTestApp } from '@/__tests__/helpers/createTestApp'
import { resetDatabase } from '@/__tests__/setup'
import { dbWorkoutBuilder } from '@/__tests__/factories/dbWorkout.factory'

describe('Workout Flow', () => {
  beforeEach(async () => {
    await resetDatabase()
  })

  it('completes a workout', async () => {
    // 🏭 Create test data
    await dbWorkoutBuilder()
      .withExercise('Squat', 3)
      .build()

    // 🔧 Render app
    const app = await createTestApp({ initialRoute: '/' })

    // 📄 Use page objects
    await app.workout.clickStartWorkout()
    await app.workout.completeExercise(0)

    // Assert
    expect(app.getByText(/complete/i)).toBeInTheDocument()

    // Cleanup
    app.cleanup()
  })
})

💡 Tips & Best Practices

  • ✅ Use page objects for complex interactions (readable, reusable)
  • ✅ Use factories for test data (avoid manual object creation)
  • ✅ Reset database before each test (isolation)
  • ✅ Cleanup after integration tests (prevent memory leaks)
  • ❌ Don't duplicate page object logic across tests
  • ❌ Don't hardcode test data (use factories)
