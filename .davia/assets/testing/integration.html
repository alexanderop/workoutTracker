🔄 Full user flow testing with router, Pinia, and real UI interactions

🎯 What Are Integration Tests?

Integration tests simulate complete user journeys through the application.

They test:

  • ✅ Multi-step workflows (create workout → add exercises → complete)
  • ✅ Navigation between pages
  • ✅ State management (Pinia stores)
  • ✅ Database interactions (IndexedDB via repositories)
  • ✅ Dialog and drawer interactions

📍 Location

src/__tests__/integration/

Example files:

  • benchmark-timer-flow.spec.ts - Complete benchmark workout flow
  • workout-management.spec.ts - CRUD operations for workouts
  • exercise-picker.spec.ts - Exercise selection workflow

🔄 Integration Test Workflow

🛠️ Core Helper: createTestApp()

The createTestApp helper renders the full application with all necessary plugins.

File: src/__tests__/helpers/createTestApp.ts

What It Provides

  • 🔌 Router (Vue Router with memory history)
  • 📦 Pinia (state management)
  • 🌍 i18n (internationalization)
  • 👤 user-event (realistic user interactions)
  • 📄 Page Objects (reusable test helpers)
  • 🔍 Testing Library queries (getByRole, getByText, etc.)

Basic Usage

import { createTestApp } from '@/__tests__/helpers/createTestApp'
import { resetDatabase } from '@/__tests__/setup'

beforeEach(async () => {
  await resetDatabase()
})

it('completes a workout flow', async () => {
  const app = await createTestApp({ initialRoute: '/' })

  // Navigate
  await app.navigateTo('/workout/active')

  // Interact using page objects
  await app.workout.clickStartWorkout()

  // Or use raw Testing Library queries
  const button = app.getByRole('button', { name: /complete/i })
  await app.user.click(button)

  // Always cleanup
  app.cleanup()
})

📦 Page Objects

Page Objects encapsulate common UI interactions into reusable methods.

Location: src/__tests__/helpers/pages/

Available Page Objects

  • app.common - Dialogs, navigation, alerts
  • app.builder - Workout builder interactions
  • app.workout - Active workout page
  • app.queue - Exercise queue drawer
  • app.benchmarks - Benchmark list page
  • app.benchmarkForm - Create/edit benchmark form
  • app.benchmarkDetail - Benchmark detail view

Example: Using Page Objects

const app = await createTestApp()

// Navigate to benchmarks
await app.benchmarks.navigateToList()

// Fill benchmark form
await app.benchmarkForm.fillName('Fran')
await app.benchmarkForm.addExercise('Thrusters', 21)
await app.benchmarkForm.addExercise('Pull-ups', 21)

// Submit
await app.benchmarkForm.submit()

// Wait for dialog
await app.common.waitForDialog()
const confirmButton = app.common.getDialogButton('Confirm')
await app.user.click(confirmButton)

app.cleanup()

⚠️ Critical Requirements

1️⃣ Always Reset Database

import { resetDatabase } from '@/__tests__/setup'

beforeEach(async () => {
  await resetDatabase()
})

Why? Tests must be isolated. Without reset, data from one test leaks into another.

2️⃣ Always Cleanup

it('my test', async () => {
  const app = await createTestApp()
  // ... test code ...
  app.cleanup() // ✅ REQUIRED
})

Alternative using setup/teardown:

import { cleanupIntegrationTest, setupIntegrationTest } from '../helpers/integrationSetup'

beforeEach(setupIntegrationTest)
afterEach(cleanupIntegrationTest)

3️⃣ Wait for Async Operations

import { waitFor } from '@testing-library/vue'

await app.navigateTo('/workout')
await waitFor(() => {
  expect(app.router.currentRoute.value.path).toBe('/workout')
})

🎓 Real Example

File: src/__tests__/integration/benchmark-timer-flow.spec.ts:12-60

import { createTestApp } from '@/__tests__/helpers/createTestApp'
import { resetDatabase } from '@/__tests__/setup'

describe('Benchmark Timer Flow', () => {
  beforeEach(async () => {
    await resetDatabase()
  })

  it('completes a ForTime benchmark', async () => {
    const app = await createTestApp({ initialRoute: '/benchmarks' })

    // Navigate to create benchmark
    await app.benchmarks.clickCreateButton()

    // Fill form
    await app.benchmarkForm.fillName('Cindy')
    await app.benchmarkForm.selectType('fortime')
    await app.benchmarkForm.addExercise('Pull-ups', 5)

    // Submit
    await app.benchmarkForm.submit()

    // Start benchmark
    const startButton = app.getByRole('button', { name: /start/i })
    await app.user.click(startButton)

    // Complete exercise
    await app.workout.completeExercise(0)

    // Verify completion
    expect(app.getByText(/benchmark complete/i)).toBeInTheDocument()

    app.cleanup()
  })
})

💡 Tips & Best Practices

  • ✅ Use page objects for complex interactions (reduces duplication)
  • ✅ Use getByRole for interactive elements (accessible queries)
  • ✅ Use waitFor for async operations (navigation, API calls)
  • ✅ Test user behavior, not implementation details
  • ❌ Don't use querySelectors (use Testing Library queries)
  • ❌ Don't skip cleanup (causes memory leaks and test pollution)
