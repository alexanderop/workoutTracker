Workout Execution

Real-time workout tracking with state machines and specialized timers for each workout type.

🏋️ Supported Workout Types

  • Strength - Set-based training with rest timers
  • AMRAP - As Many Rounds As Possible in fixed time
  • EMOM - Every Minute On the Minute intervals
  • Tabata - 20 sec work / 10 sec rest intervals
  • For Time - Complete exercises as fast as possible

📊 Execution Flow

🎮 Timer State Machines

Location: src/composables/timers/

Each workout type has a dedicated composable with state management:

💪 useRestTimer()

For: Strength workouts

  • Countdown timer between sets
  • Play/pause/reset controls
  • Audio notification when complete

🔄 useAMRAPTimer()

For: AMRAP workouts

  • Count up timer to track total time
  • Round tracking and rep logging
  • Auto-stops at configured duration

⏰ useEMOMTimer()

For: EMOM workouts

  • Interval-based timing (1 minute cycles)
  • Work period → Rest period auto-transitions
  • Tracks current minute and total rounds

⚡ useTabataTimer()

For: Tabata workouts

  • Fixed 20 sec work / 10 sec rest intervals
  • 8 rounds standard protocol
  • Visual and audio cues for transitions

🏃 useForTimeTimer()

For: For Time workouts

  • Count up timer until all exercises complete
  • Track exercise completion status
  • Final time recorded as benchmark

🔧 State Machine Pattern

Each timer composable follows this structure:

export function useTimer() {
  const state = ref('idle') // idle | running | paused | complete
  const elapsedTime = ref(0)

  const start = () => { state.value = 'running' }
  const pause = () => { state.value = 'paused' }
  const reset = () => {
    state.value = 'idle'
    elapsedTime.value = 0
  }

  return { state, elapsedTime, start, pause, reset }
}

💾 Workout Persistence

Flow:

  1. User starts workout from template or creates custom
  2. Workout state tracked in real-time during execution
  3. On completion, workout saved to IndexedDB via workoutRepository
  4. Historical data available for progress tracking

🌐 WakeLock API

Purpose: Prevent screen sleep during active workouts

Implementation: Used in timer composables to keep screen on

  • Acquires lock when workout starts
  • Releases lock on pause or completion
  • Graceful fallback if not supported
