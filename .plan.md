# Pipeline Fix Implementation Plan

## Problem Summary

The CI pipeline is failing with **2 main categories of errors**:

### 1. Vite Plugin Configuration Issue (Primary - CRITICAL - 29 test suites failing)
**Error**: `Failed to parse source for import analysis because the content contains invalid JS syntax. Install @vitejs/plugin-vue to handle .vue files.`

**Root Cause**: Commit `5683b34` added `resolve` configuration to each test project to fix path alias resolution, but **forgot to add `plugins`** configuration. The `@vitejs/plugin-vue` plugin is defined at the root level (line 21) but is not being passed to individual test projects (`default`, `a11y`, `visual`). Each project only has `resolve` explicitly set.

**Reproduction**: Confirmed locally - `pnpm test:a11y` fails with identical error

**Affected Files**:
- 28 test suites in the `default` project (run via `pnpm test:coverage`)
- 1 test suite in the `a11y` project (run via `pnpm test:a11y`)
- All attempting to import `.vue` files without the Vue plugin available

**Current config** (vitest.config.ts lines 72-113):
```typescript
projects: [
  {
    resolve,  // ← Has this (added in 5683b34)
    // Missing: plugins  ← NEEDS THIS
    test: { name: 'default', ... }
  },
  // ... other projects also missing plugins
]
```

**Fix Impact**: This fix alone should resolve 29 of 31 failing test suites.

---

### 2. Pinia Context Missing in Browser Tests (Secondary - 22 test failures)
**Error**: `MissingAPIError: IndexedDB API missing. Please visit https://tinyurl.com/y2uuvskb` / `DatabaseClosedError`

**Root Cause**: The `timer-audio.spec.ts` and `wake-lock.spec.ts` tests use composables that depend on Pinia stores (`useSettingsStore()`), but the `withSetup()` helper creates a Vue app **without Pinia installed**. When composables try to access stores, there's no Pinia context in the app, causing store initialization to fail and trigger IndexedDB errors.

**Call chain**:
1. Test calls `withSetup(() => useTimerAudio())` which creates a NEW Vue app
2. `withSetup()` app has no Pinia installed (only core Vue)
3. Composable `useTimerAudio()` calls `useSettingsStore()`
4. Store has no Pinia context in `withSetup()` app
5. **ERROR**: Store initialization fails, IndexedDB errors cascade

**Affected Tests**:
- `src/__tests__/browser/timer-audio.spec.ts` (9 tests)
- `src/__tests__/browser/wake-lock.spec.ts` (13 tests)

**Note**: These failures may only become visible after fixing Issue #1.

**After**:

  {

      name: 'default',
      include: ['src/__tests__/**/*.spec.ts', '!src/__tests__/a11y/**', '!src/__tests__/visual/**'],
    },
  },
  {

      name: 'a11y',
      include: ['src/__tests__/a11y/**/*.spec.ts'],

- `VitePWA()` - PWA plugin

By explicitly adding `plugins` to each project config (just like `resolve` was added), the Vue plugin will be applied during test execution.

1. Line 74: Add `plugins,` before `resolve,`

### Step 2: Add Pinia to `withSetup()` Helper

**File**: `src/__tests__/helpers/withSetup.ts`

**Problem**: Browser tests call `setActivePinia(createPinia())` globally, but then `withSetup()` creates a new Vue app without Pinia installed. When composables try to use stores, there's no Pinia context in the app.

**Change**: Install Pinia in the `withSetup()` app to match the real app environment.

**Before**:
```typescript
import type { App } from 'vue'
import { createApp } from 'vue'

export function withSetup<TResult>(composable: () => TResult): [TResult, App] {
  let result: TResult
  const app = createApp({
    setup() {
      result = composable()
      return () => {}
    },
  })
  app.mount(document.createElement('div'))
  // @ts-expect-error - result is assigned synchronously in setup
  return [result, app]
}
```

**After**:
```typescript
import type { App } from 'vue'
import { createApp } from 'vue'
import { createPinia } from 'pinia'  // ← ADD

export function withSetup<TResult>(composable: () => TResult): [TResult, App] {
  let result: TResult
  const app = createApp({
    setup() {
      result = composable()
      return () => {}
    },
  })
  app.use(createPinia())  // ← ADD
  app.mount(document.createElement('div'))
  // @ts-expect-error - result is assigned synchronously in setup
  return [result, app]
}
```

**Why this works**:
- Each `withSetup()` call creates its own Pinia instance via `app.use(createPinia())`
- Composables that use stores (like `useTimerAudio` → `useSettingsStore`) will work correctly
- Tests that manually call `setActivePinia()` will still work (tests can override the app-level Pinia)
- Matches the real app environment where Pinia is always available

**Alternative considered**: Remove `setActivePinia()` calls from browser tests and only rely on `withSetup()`'s Pinia. However, keeping both allows tests more flexibility in controlling store state.
